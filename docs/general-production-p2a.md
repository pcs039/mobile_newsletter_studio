# 일반 제작 P2 A 수동 음성과 프로젝트 폰트 보강

2026년 11월 1일. 기준은 고정 Staging `51537b5`와 P1 문서 커밋 `dc74bbd`다. P2-B 신규 발행호 제작과 R1-B는 실행하지 않는다.

## 수동 음성 연결

기존 `updateProjectAudioArticleLink`는 기존 연결을 두 번의 PATCH로 정리한 뒤 음성 메타데이터와 기사 연결을 각각 갱신했다. 중간 오류 시 일부 요청만 반영될 수 있었고, 음성 파일 연결과 기사 `audio_source` 선택도 분리되어 있었다. 기존 기사 저장 RPC는 블록·링크 저장 계약까지 포함하므로 수동 음성 연결용으로 재사용하지 않는다.

새 `manage_newsletter_manual_audio_link` 함수 하나가 다음을 한 트랜잭션에서 수행한다.

- 서버가 확인한 프로젝트·호출자와 같은 프로젝트의 업로드 음성/기사만 허용한다. 서비스 역할만 실행할 수 있으며 사용자·담당자도 DB에서 재확인한다. 프로젝트 비밀번호 접근은 기존 API 인증을 유지한다.
- 프로젝트 → 기사 → 음성 순서로 잠근다. 프로젝트의 음성 연결 정보와 선택 파일의 메타데이터를 포함한 revision을 조회하고 저장 시 CAS로 비교한다. 다른 음성·기사의 변경도 보수적으로 충돌 처리할 수 있다.
- 기존 양방향 연결 정리, 새 연결, `audio_source=uploaded`, 대본·검수 정보 저장을 함께 커밋한다. 실패하면 모두 롤백한다. 해제 시에는 해당 수동 연결만 정리한다.
- AI 음성이 선택된 대상 기사 또는 TTS 처리 중인 기사는 새 수동 연결을 거절한다. AI에서 수동으로 바꾸려면 작성 화면에서 먼저 명시적으로 변경한다. 기존 `ai_audio_id`, TTS 상태와 파일은 변경하지 않는다. 이전 수동 참조를 해제해도 선택된 AI 음성을 끄지 않는다.
- 생략된 대본·검수 필드는 유지한다. 불일치한 기존 양방향/다중 연결은 자동 복구하지 않고 충돌로 안내한다. 파일·구버전 메타데이터 삭제는 하지 않는다.

멱등성은 **요청한 연결과 명시한 메타데이터가 이미 동일하면 UPDATE 없는 성공**으로 구현한다. 별도 요청 이력 테이블이나 영구 receipt는 만들지 않는다. 이후 다른 상태로 바뀌었다면 오래된 revision으로 되돌릴 수 없다. 새로운 편집 요청과 구별되는 영구 요청 이력 조회 기능을 제공하는 것은 아니다.

기존 `/api/project-audio-links`에 인증된 GET 상태 조회를 추가하고 POST는 새 RPC만 호출한다. 예전 다중 PATCH fallback은 제거한다. RPC가 설치되지 않으면 503으로 닫힌다. UI는 상태를 먼저 읽고 저장 중 중복 클릭을 막으며, 응답 유실 시 입력을 잠그고 사용자가 같은 payload로 결과를 확인하게 한다. 자동 재시도는 없다. 충돌 시 초안을 남기고 명시적인 최신 상태 불러오기를 제공한다. 오류에 서버 키나 DB 원문 오류를 전달하지 않는다.

보호 범위는 이 수동 연결 작업의 CAS와 트랜잭션이다. 일반 기사 편집 전체를 새 revision 저장 시스템으로 바꾸지는 않았다. 다른 편집 화면과 병행할 때는 최신 저장본을 다시 불러온 뒤 음성 방식을 변경한다.

## 폰트 설정

원인은 `/projects/[projectId]/settings`에서 `ProjectCreateForm`으로 폰트 목록을 전달하지 않은 것이다. 추가로 패밀리 대표 Regular만 선택 목록에 남으면 기존 Bold ID 등이 옵션에서 사라질 수 있었다. PATCH에서 폰트 필드가 빠지면 기존 repository는 null로 저장할 수 있었다.

- 설정 화면에서도 기존 `getFontAssets`를 사용한다. 현재 선택을 확인할 수 있도록 비활성 항목을 포함해 읽되, 새로운 선택 후보는 기존 활성 파일·웹폰트 허용·패밀리 활성/웹폰트 정책을 따른다.
- 현재 선택 ID가 대표 굵기 목록에서 빠지거나 목록 조회가 실패해도 해당 ID의 ‘기존 선택 유지’ 옵션을 남긴다. 비활성 폰트를 새로 렌더링 허용하거나 전체 프로젝트 폰트를 초기화하지 않는다.
- 폼 필드가 없으면 기존 ID를 유지한다. API·repository도 누락된 필드는 PATCH하지 않는다. 사용자가 ‘시스템 기본 글꼴’을 명시적으로 선택한 빈 값만 해당 역할의 참조를 해제한다.
- 제목·본문 기본값만 이 변경 대상이다. 기사별 폰트, 패밀리·굵기 데이터, 라이선스와 Storage 원본은 변경하지 않는다.

Staging 읽기 전용 등록 비교: 파일 289개, 패밀리 243개, 활성·웹폰트 허용 파일 285개다. 기존 선택 정책을 통과하는 파일 285개가 242개 패밀리 대표로 묶인다. 누락 패밀리 참조와 빈 파일 경로는 0개였다. 이 집계는 Storage 파일 전체의 실물 검사가 아니다.

## 격리 검증

- 실제 PostgreSQL: 새 임시 클러스터·Unix 소켓만 사용한다. 원격 URL·앱 키를 받지 않는다. 승인 guard와 스키마 선행 조건, 권한, 조회 무변경, 연결·교체·해제·이동, 대본 보존, 두 실패 지점의 전체 롤백, 프로젝트 격리, AI 연결 보존, stale 충돌, 응답 유실 재조회, 동일/경쟁 동시 요청을 검증한다.
- API·UI 모의 테스트: GET 선조회, 신뢰된 서버 actor, 입력/동일 출처 검증, 권한 거절, 누락 RPC의 안전한 차단, 오류 분류, 응답 본문 중단, 중복 클릭 방지, 정확히 같은 payload 확인을 검증한다.
- 폰트 모의 테스트: 패밀리 필터·현재 Bold/비활성/목록 누락 선택 보존, 설정 페이지의 목록 전달, 실제 React 폼 → 실제 API → 실제 repository와 메모리 DB transport를 거친 저장·재접속·누락 필드 보존·명시 해제를 검증한다. 모든 fetch는 모의 DB/앱 경로로 제한하며 AI 호출은 없다.
- PostgreSQL 18/18 통과. 관련 API·작성·미리보기·발행·폰트·TTS 회귀는 122개 통과, 실패 0, 선택적 PGlite 런타임을 요구하는 기존 발행 SQL 6개는 미실행이다. 해당 발행 SQL은 변경하지 않았다.
- TypeScript, lint, Webpack build 통과. lint는 기존 경고 3개이며 신규 오류·경고는 없다. 실환경 저장·업로드·모바일 검증은 하지 않았다.

## DB 적용 조건과 P2 B 판정

SQL 초안은 `supabase/schema_v1_46_manual_audio_links.sql`이다. 변경 범위는 서비스 전용 함수 1개와 해당 함수의 실행 권한, PostgREST schema reload다. 새 테이블·컬럼·인덱스·데이터 backfill은 없다. 기존 스키마 중 v1.43의 `tts_generation_state` 등을 사전 검사하며 승인용 세션 설정 없이는 중단한다.

**코드·격리 구현은 완료했지만, 현재 고정 Staging에서 P2-B 신규 제작을 시작하는 판정은 보류한다.** 다음의 승인·적용이 필요하다.

1. Staging `mvrkpmffuhcqwisqvpqi`의 신원·선행 컬럼·역할을 재확인한 뒤, 해당 DB에만 v1.46 적용 승인을 받는다. 이번 작업에서는 적용하지 않았다.
2. 승인된 코드 SHA를 Staging 전용으로 적용한다. 신규 브랜치의 자동 Vercel 배포는 `vercel.json`에서 비활성화했다. 고정 Staging·Production·기존 PR은 변경하지 않는다.
3. 인증된 일반 수동 음성 GET과 권한·RPC 상태를 확인한다. 함수가 없거나 오류가 있으면 수동 저장을 막으며 이전 PATCH 경로로 돌아가지 않는다.
4. 별도 P2-B 쓰기 승인 후 신규 테스트 발행호에만 생성·저장·업로드·연결 검증을 진행한다. 기존 화성시 7건과 정상 자산은 대상에서 제외한다. 공식 발행·외부 공개는 별도 범위다.

적용 전에는 데이터 복구 작업이 없다. 적용 후 문제가 생기면 수동 연결 쓰기를 중단하고 상태를 읽어 확인한다. 코드 복귀 시 함수는 남겨도 기존 데이터에 자동 작용하지 않는다. 함수 제거가 필요하면 새 호출자가 없는 것을 확인한 뒤 별도 승인으로 수행한다. 정상 연결이나 파일을 되돌리기 위해 임의 삭제·재생성을 하지 않는다.
