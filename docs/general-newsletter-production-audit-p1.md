# 일반 모바일 소식지 반복 생산 기능 실사 P1

기본적인 새 발행호는 기존 프로젝트·기사·디자인·파일·발행 화면을 조합하여 사람이 제작할 수 있는 경로가 있다. 다만 신규 발행호의 저장부터 발행까지 성공했다고 판정할 단계는 아니다. 이번 P1은 로그인된 Staging의 입력 화면, 기존 저장본 출력, 읽기 전용 데이터와 저장 코드를 확인했다. 실제 신규 생성·저장·업로드·발행과 AI 장애 상태의 실행 검증은 P2 대상으로 남긴다.

## 기준과 검증 범위

- 실사일: 2026년 10월 31일~11월 1일, Asia/Seoul.
- Staging 기준: `51537b51176b9427368c6705a2cf4549872fe5eb`, PR #289. PR #287~#291은 OPEN 상태다.
- 로컬 실사 브랜치: `codex/general-production-p1`. Staging SHA에서 직접 분기하여 PR #290 문서와 PR #291 실험 코드를 선행 의존성으로 포함하지 않았다. R1-B는 보류한다.
- 실제 화면: `canva-staging.datadiction.co.kr`의 신규 프로젝트 폼과 기존 비공개 `canva-e2e-test` 프로젝트. 기사 작성·디자인·검수, 프로젝트 설정, 이미지·디자인·음성 관리, 발행, 관리자 미리보기와 e-book 화면을 조회했다.
- 코드 및 데이터 조사는 Staging으로 한정했다. Production, 화성시 샘플 7건, 음성·공유 링크, DB·Storage, 기존 PR은 변경하지 않았다. 기존 stash 두 개도 유지했다.
- 입력 화면의 탭·접기·펼치기와 미저장 빈 폼의 구성만 확인했다. Composition의 자산 선택·배치·상태는 자동 저장되므로 조작하지 않았다. 발행·검토 링크 발급·AI 생성 버튼도 실행하지 않았다.
- 기존 수동 업로드 MP3는 관리자 플레이어의 재생 시간이 약 0.22초에서 5.39초로 진행되고 브라우저 미디어 오류가 없음을 확인했다. 실제 사람의 청감·실기기 검증과 기사 연결 후 재생 성공을 의미하지 않는다.

| 분류 | 의미 |

| A | 해당 범위의 일반 관리자 입력·조회·출력 경로를 화면에서 확인했으며 별도 개발이 필요하지 않음 |

### 저장본에서 확인한 범위

기존 비공개 fixture에는 기사 4건, 일반 이미지 자산 0건, 디자인 자산 9건, 음성 행 2건, e-book 페이지 0건이 있었다. 디자인 자산 중 활성·승인된 자산은 4건이다. 행사 기사의 저장본에는 문단과 URL 버튼이, 정책 기사의 저장본에는 기존 디자인 이미지와 HTML 본문 및 AI 음성 재생 UI가 표시되었다. 정책 기사 이미지의 실제 디코딩 크기는 1152×768이며 로딩 완료 상태였다.

수동 업로드 음성 1건은 미연결이며 검수 메모에도 실제 기사 낭독문이 아닌 QA 재사용 파일로 명시되어 있다. 이를 정상 기사 음성 제작 사례로 집계하지 않는다. 발행 화면의 ‘음성 파일 2개·준비됨’ 표시도 모든 기사에 음성이 연결되었다는 의미가 아니다.

### 공통 기능의 차이

- 일반 프로젝트 표지·일반 기사 탐색과 화성시의 전용 표지·관심분야 4종·요약/상세 인라인 흐름은 다른 제작 계약이다. 새 slug만 만들면 화성시 UI가 생기는 구조가 아니다.
- 일반 기사에는 업로드/AI 중 선택한 기사 음성 경로가 있다. 화성시의 독립된 요약·상세 14개 음성, 대본 및 재생 역할을 일반 작성자가 관리하는 범용 UI는 별도 연결 기능 D다. 현재 특수 메타데이터를 수동 복사하는 방법을 제작 절차로 채택하지 않는다.
- HTML e-book chrome은 재사용 후보지만 일반 `/newsletters/[slug]/ebook`는 페이지 이미지 경로다. 같은 HTML 원고를 모바일·PC 책장에 함께 공급하는 일반화는 D다.
- 화성시 전용 의견·간단 설문·시연 공유 권한은 새 일반 발행호로 자동 확대되지 않는다. 일반 설문·이벤트 기능과 별도 계약으로 유지한다. 이번에 댓글을 재도입하지 않는다.
- 기존 샘플 안전 편집은 기존 데이터 보존을 위한 경로다. 일곱 유형을 처음부터 만들거나 완성 발행호 전체를 복제하는 범용 제작 기능으로 해석하지 않는다.

## AI 장애 시 수동 제작 가능 여부

| 작업 | 수동 대안 | 현재 판단 |
| --- | --- | --- |
| 초안·제목·요약 | 사람이 직접 작성·붙여넣기 | 일반 입력 화면 확인 |
| 사진·삽화 | 권리 확보한 기존 이미지 업로드 | 업로드 UI 확인, 새 업로드는 P2 |
| 디자인 | 기존 SVG/PNG 등 제작 자산 + HTML 제목·본문 + Composition 배치 | 기존 저장본 결합 출력 확인, 새 배치/저장은 P2 |
| 음성 | 사람이 녹음하거나 기존 보유한 완성 MP3를 업로드·기사 연결 | 관리자 파일 재생 확인, 신규 기사 연결·교체는 P2 |
| 검수 | 저장본 미리보기·기사 검수·사람의 체크리스트 | 화면 확인 |
| 발행 | 작성자 직접 발행 또는 기관 검수 후 발행 | 기능 화면·서버 계약 확인, 발행 미실행 |

수동 제작을 위해 새로운 AI 서비스나 R1-B를 도입할 필요는 없다. P2에서는 자동 생성 기능을 선택하지 않고 작업하며, OpenAI/이미지 생성 요청이 0회인지 함께 확인한다. 외부 Canva 연결이나 유료 외부 도구를 수동 제작의 필수조건으로 삼지 않는다.

## 우선 보완할 기능

| 순위 | 문제와 근거 | 최소 개선 범위 |
| --- | --- | --- |
| 1 | 프로젝트 설정에서 활성 폰트 없음 표시. 신규 폼·디자인 화면에는 폰트가 표시되지만 `settings/page.tsx`는 `ProjectCreateForm`에 fonts를 공급하지 않음 | 기존 폰트 조회·prop 전달 재사용. 선택값이 없는 재저장에서 기존 폰트 참조가 비워질 가능성은 추정 위험이며 저장 재현은 하지 않음. P2 복제 fixture에서 보존 확인 |
| 2 | 수동 음성의 연결·모드가 분리됨. `updateProjectAudioArticleLink`는 기존 연결을 먼저 PATCH로 정리하며 기사 `audio_source`는 변경하지 않음 | 수동 모드·기사 연결 동선 정리와 실패 시 이전 연결 보존. 새 테이블·복구 시스템 없이 검토하고 DB 변경이 필요하면 별도 최소안 제시. 체크리스트도 파일 수와 기사 연결/재생 확인을 구분 |
| 3 | 디자인은 기사·텍스트·배치·폰트에 따라 저장 방식과 공개 조건이 다름. 일반 이미지 소재 정보는 입력 안내와 실제 수정 UI 사이에 차이가 있음 | 현재 저장 상태·공개 조건 안내를 재사용하고 P2에서 reload 후 결과 비교. 출처·권리·대체텍스트의 기존 입력 경로를 연결하거나 미지원 범위를 명시. 이미 표시된 ‘공개 미반영’ 슬롯을 구현 완료로 보이게 하지 않음. 미지원 슬롯 전부 구현은 제외 |
| 4 | 문단에 Markdown 강조 기호를 넣으면 실제 reader에 그대로 표시됨 | 현재 지원 서식과 일반 텍스트 입력 안내, 정보박스·인용문 활용 안내를 보완. 새 WYSIWYG 편집기는 선행 개발하지 않음 |
| 5 | 일반 HTML 기사와 PC HTML e-book·화성시 전용 유형 연결이 없음 | 후속 범용화 D로 분리. 기존 페이지 이미지 e-book을 수동 대안으로 검증한 뒤 필요한 HTML 연결만 결정. 기본 P2 제작을 지연시키지 않음 |

## 신규 테스트 소식지 시나리오와 P2 최소 계획

이 절의 프로젝트와 파일은 아직 생성하지 않았다. 쓰기 승인을 받은 뒤 Staging 신규 테스트 발행호 하나에만 실행한다. 후보 slug는 `repeat-production-p2-2026-11`이며 실제 사용 가능 여부는 생성 직전 확인한다. 화성시 7건을 복제·수정하거나 Production 데이터를 사용하지 않는다.

### 제작할 한 개 호

| 구성 | 준비물 | 검증할 저장 및 출력 |
| --- | --- | --- |
| 표지 1개 | 권리 확보한 표지 이미지, 수동 제목·호수 | 표지 설정·업로드 후 재진입 시 동일, 모바일 표지 표시 |
| 기사 1 이미지와 HTML | 직접 작성 원고, 사진 1장, 소제목·캡션 | 제목·요약·문단·이미지·캡션을 저장·수정·재조회 |
| 기사 2 행사와 URL | 검수용 일정·장소·HTTPS 링크 | publicInfo·CTA 저장 후 실제 링크와 표시 순서 확인 |
| 기사 3 배경과 텍스트 | 기존 보유 웹용 배경/상단 삽화, 인용문 | 디자인 자산 승인·활성, 배치·텍스트·폰트·ready와 저장본 표시 일치 |
| 수동 음성 | 위 기사에 정확히 대응하는 보유 녹음 MP3 3개 | uploaded 모드·파일·대본 연결, 모바일 재생, 수정 후 연결 보존 |
| 선택 PC 지면 | 사람이 제작한 같은 원고의 페이지 이미지 | 페이지 순서·핫스팟·이미지 e-book 출력. HTML 자동 변환으로 집계하지 않음 |

### 실행 순서와 통과 조건

1. 우선 보완 1·2의 최소 수정 범위를 정하고, 필요한 코드 검증은 새 fixture 대상 모의 테스트로 수행한다. R1-B·새 제작 엔진·신규 템플릿 시스템을 포함하지 않는다.
2. 신규 Staging 프로젝트·기사·파일 쓰기 범위가 승인되면 표지와 기사 3건을 일반 UI로 제작한다. AI 생성은 사용하지 않는다.
3. 각 단계에서 저장 → 새로고침 → 재편집 → 관리자 저장본 미리보기를 확인한다. 변경하지 않은 기사·블록 내용·Composition·폰트·음성 연결이 보존되는지 비교한다.
4. 수동 음성의 첫 연결과 다른 보유 MP3로의 교체를 확인한다. 실패 모의 테스트에서 기존 연결 유지, 실제 reader에서 업로드 음성 선택, 기사 이동 시 재생 정지를 확인한다. API 호출을 위해 기존 sample TTS 경로를 사용하지 않는다.
5. 390px·520px, 가로 844×390과 PC 1366×768에서 제목·이미지·본문·URL·음성 출력 확인. 이미지 e-book을 준비했다면 해당 경로의 PC 표시도 별도로 확인한다. 실제 휴대전화 결과는 자동화와 구분한다.
6. 관리자 미리보기까지를 기본 P2 종료점으로 삼는다. 공식 발행·외부 검토 링크 발급·익명 공개 및 발행 취소 테스트는 별도 승인된 신규 fixture에 한해 진행한다. 발행 후 수정 즉시 반영과 정기호 draft 공개 범위도 그때 검증한다.

통과 기준은 Codex의 DB 직접 편집 없이 일반 작성자가 한 호의 표지·기사 3건·디자인·수동 음성을 저장·수정·재조회하고 미리볼 수 있는 것이다. 새 업로드 파일의 무결성과 실제 재생·기사 연결을 확인하고 AI 호출은 0회여야 한다. 출처/권리 상태는 별도로 검수한다. 현재 자동 체크리스트의 ‘준비됨’만으로 통과시키지 않는다.
