# Visual Director information graphic v1

Saved article → server director check → pure structured specification → explicit internal SVG rendering → active draft card asset → separately approved article candidate.

Five types: steps, schedule, comparison, key_numbers, checklist. Only the director's information_graphic strategy with needsInformationGraphic=true executes. Other strategies are hidden; hybrid is advisory. Explicit numbered steps/method arrows, structured publicInfo date/number fields, labelled numeric comparison pairs and bullet checklists are supported. Arbitrary prose, maps, missing facts, discontinuous step numbering and ambiguous input require human review. No inferred number/date/step, semantic shortening or ellipsis. Visible paragraph blocks take precedence over legacy body; hidden blocks never become graphic content. Each item traces a source path/block and original stored substring.

Spec v1: purpose, type, title, items with source provenance, 4:5 or1:1, public_cards_v1 layout, sourceArticleId, needsHumanReview/issues. Title≤40, labels≤20, descriptions≤60,2–6 items. Combined layout capacity also gates long descriptions; no silently dropped items. Square is limited to key-number graphics with≤3 items. Original article/blocks/links are never mutated.

Renderer is a pure escaped SVG, native1000×1250 or1000×1000; no engine/library dependency, rasterization, external fonts/references/scripts or third-party API. Public cards prioritize large text and whitespace, dark text on pale/white panels, primary-color rule/edge accents, no shadows/advertising. Assets remain SVG (not PNG) using the existing supported rendition type.

Server `/api/project-content/information-graphic`: admin/project auth, same-origin, bounded allowlisted input, saved same-project article and authoritative project color. prepare/status only read; generate requires a fresh SHA-256 key. Key covers project/article IDs, stable source snapshot digest, director, spec, renderer version and palette. Deterministic asset UUID/path and x-upsert=false prevent duplicate file/row registration. Existing success is checked before rendering. Existing private file without a confirmed row becomes unknown; no overwrite/re-render. Concurrent duplicate upload returns in_progress; UI bounded status-only polling never repeats generate. Uncertain transport/registration offers status checks, not automatic retry. Article edits invalidate the source-keyed UI state.

Existing processing jobs cannot represent an internal provider under their DB constraint. No fake AI/Canva job is inserted and no migration is added. Durable receipts are the unique asset row and immutable private file. This avoids a new orchestration/claim schema; concurrent pure SVG computations may both occur, but only one private file/asset can be created.

Reuse existing private design-production-assets upload/record transport. Asset type=card_frame, source=internal (“앱 생성”), draft/active, project reuse classification. Strict metadata.informationGraphic: articleId, graphicType, specVersion, generationKey. Asset-ID admin preview/management mapper exposes no raw path and serves recognized internal SVG inline under restrictive sandbox CSP. Other SVG/PNG and public article renderer behavior stay unchanged. Recommended use=image_block; approval and application remain explicit future actions.

No GPT Images/Canva/Adobe, migration/RPC/dependency, automatic approval/application or publication. Tests use mocks/local HTTP for interactions and transport; all actual registration validation must use non-production resources. Production data is never modified by development validation.
