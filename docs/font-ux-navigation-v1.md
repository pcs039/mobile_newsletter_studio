# 글꼴 탐색·관리 UX v1

기준 main: `13e9176d02ac886773d84ad140919a718aa55fdf`.

## 범위

- 기사 글꼴 편집은 기존 `2. 디자인`만 사용한다. 작성 고급 설정의 정렬 기능은 유지한다.
- 패밀리 검색 + 20개 단위 이전/다음 탐색. 검색/페이지 이동은 저장 ID를 변경하지 않는다.
- 명시적인 패밀리 선택만 기존 representative font asset ID를 로컬 폼에 반영한다. 저장은 기존 기사 저장 버튼/Context/RSC 경로를 그대로 사용한다.
- 등록 굵기/스타일, 저장 참조 파일의 metadata, 패밀리 미리보기(400/normal)를 구분한다. 실제 기사 weight/style은 기존 CSS를 따른다. 파일별 굵기 적용 기능은 추가하지 않는다.
- 관리 목록은 DB family ID로 묶고 legacy 단일 파일은 별도 그룹으로 유지한다. 이름/파일명 검색, 유효 사용 상태 필터, 패밀리 이름/그룹 내 가장 최근 파일 등록 시각 정렬, 20개 단위 페이지를 제공한다.
- 파일·스타일/기존 활성화 버튼/사용조건/미리보기는 기본 접힌 상세에서 확인한다. 기존 활성화/비활성화 API와 영향은 그대로이며 발행본 영향 안내를 추가한다.
- 일괄 등록은 기존 분석·업로드·complete 재확인·실패 재시도 로직을 유지한다. 성공/실패/제외 개수를 요약하고 성공만 있는 경우 상세를 접는다. 실패/분석 제외가 있으면 자동으로 접지 않으며, 사용자가 상세를 닫고 다시 열 수 있다. 파일/선택/token state는 접기로 제거하지 않는다.
- ZIP 등록 성공 결과도 요약 + 기본 접힌 상세로 표시한다. 개별 등록/ZIP/일괄 등록 기능은 유지한다.

## 변경하지 않는 계약

API/RPC/DB/Storage/인증/환경변수/프로젝트 담당자/공개 reader/font-css/상속/Composition 저장 hook/React Context/RSC 변경 없음. 비활성 폰트가 기존 발행본에도 영향을 주는 정책은 변경하지 않는다. 호환성 이슈 #239는 별도다.

- 600개 패밀리의 deterministic 검색/페이지 이동, ID 유지, 서로 다른 family ID 미병합.
- 등록 굵기와 기사 CSS 구분, 기존 실제 웹폰트 로드/실패 안내 유지.
- 관리 검색·사용 상태·최근 등록 정렬·기본 접힘, 상태 변경 callback 유지.
- 업로드 성공 접힘, 부분 실패/분석 제외 노출, 상세 재열기 시 재요청 없음. 기존 duplicate/complete 재시도 회귀.
- 전체 테스트/TypeScript/lint/Webpack/diff 및 Staging 수동 로그인 QA 결과는 PR 본문에 기록한다.

Production 배포·write, migration, 외부 생성 호출 없음. PR #226/#229 및 stash 2개 보존. PR은 병합하지 않는다.
