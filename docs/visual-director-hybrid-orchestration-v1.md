# Hybrid visual orchestration v1

A pure v1 plan chooses one primary and at most one optional secondary: strategy, hero/supporting purpose, required, assetRequired, reasons, humanReviewRequired and deterministic executionOrder. No orchestrator persistence, provider client, renderer, migration or article application is introduced.

Supported combinations: institution+graphic, institution+HTML, institution+Canva recommendation only, conceptual GPT image+graphic, graphic+HTML. Existing Director hybrid real-photo+information evidence is retained. New combinations require explicit supporting evidence: actual event record with at least two structured public fields for Canva, conceptual+information without factual-photo needs for GPT, or at least three non-list prose lines totalling 400 characters for an HTML companion. Oversized list items alone never trigger hybrid. Simple single-strategy articles retain their existing paths. Named real people remain photo-first even when the article also discusses concepts/steps.

Pure boundaries: determineHybridPrimary, determineHybridSecondary, buildHybridVisualPlan, buildHybridExecutionState, buildHybridRecommendation. Actual photos take primary priority. Missing institutional candidates become needs_input/blocked, never GPT fallback; the operator may explicitly prepare the graphic secondary. Secondary failures preserve the primary result. HTML is completed existing text, assetRequired=false. Canva is recommendationOnly, calls the existing canonical recommender and has no execution button. Human candidate acknowledgement is not approval or application.

Existing institution matching GET, information-graphic POST and visual-asset-generation POST accept optional literal context=hybrid. The server still loads the current saved same-project article, authenticates the administrator, and recomputes the hybrid plan; a client context cannot select an arbitrary strategy. Default single-mode gates remain unchanged. Graphic spec/SVG/upload/registration reuse the existing helper. Photo availability does not prevent extracting valid secondary factual information; missing map/source/length issues still block it. GPT shares the existing spec/prompt, Staging-only origin/environment policy, conceptual/no-text constraints, job claim/receipt, terminal unknown/failed policy and draft registration. No real external provider calls are performed during this PR's validation.

Preparation order: institutional candidates first; explicit primary preparation/selection, then secondary. Primary needs_input permits explicit secondary preparation, without claiming the whole composition ready. Busy state and existing click locks prevent simultaneous automatic generation or double-click duplication. Prepare/status polling never issues another generate request. Both prepared (or an asset plus existing HTML/acknowledged Canva recommendations) yields ready_for_review; human review remains mandatory.

Hybrid key uses SHA-256 over safe article snapshot, Director, plan, stable stage recommendation digests, canonical Canva candidate IDs and orchestratorVersion v1. It excludes state transitions, selection side effects, raw Storage paths, signed URLs, private provider metadata and ephemeral preview URLs. Existing institution snapshot logic is shared rather than duplicated. Hybrid executor generation keys namespace the hybrid context and use safe source snapshots; default single-mode key contracts remain intact.

UI lives inside the existing AI visual strategy card, with primary/secondary headings and the existing controls. Source changes or changed recommendation keys mark the old context stale, hide executors, retain previous result references, and require explicit re-confirmation. A newly computed key is never approval. Assets are not deleted. Review state is session/component state; no reload persistence or DB orchestration record is claimed.

Validation uses pure/server unit fixtures and actual local React browser fixtures. Provider/file/DB endpoints are mocked; placeholder institutional/GPT thumbnails are synthetic. Existing SVG renderer is real, but local registration receipts are in-memory fixtures, not real assets. Production DB/Storage writes and external provider calls are zero. Rights/identity/visual content still require a human.

Validation result: new hybrid tests 19/19; full regression 268/268 with `node --test --test-concurrency=1`. An existing Canva UI test's 20ms timer wait was once sensitive to parallel compilation; isolated and full serial runs passed without changing that test or Canva code. TypeScript/lint/Webpack build/diff check passed, three existing warnings and zero new warnings. Browser 1440/768: no overflow/console errors; explicit selection/generation, duplicate result reuse without another generation, missing primary input, preserved primary on secondary failure, article/recommendation-key stale, explicit re-confirmation and non-hybrid stale-plan dismissal all verified. Local counters: two internal SVG fixture creations, one simulated GPT fixture creation, three retained in-memory asset receipts; actual external provider/DB/Storage calls all zero. No live Canva/GPT E2E was performed.
