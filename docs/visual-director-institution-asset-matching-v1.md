# Institution asset matching v1

Read-only, stateless matching under the existing AI visual strategy card. A saved same-project article whose director primary is institution_asset and needsRealPhoto is true can request up to three candidates. Hybrid and other strategies do not run this path. Candidate selection is local UI state, not approval or application.

The pure spec contains sourceArticleId, explicit subject type/names, bounded context/location/time terms and preferred real-photo kinds. Only labelled subjects or literal named title patterns are recognized; person names are not inferred from arbitrary prose. Ambiguous subjects produce no candidate. Classifier derives real_person_photo/event_photo/facility_photo/place_photo/poster/character/illustration/other from existing name/alt/usage note. There is no vision, OCR or face verification. Text evidence can be wrong: every candidate needs human confirmation of identity, date/edition, permission and rights.

Candidate gates: institution source, same project, active, not archived/discarded, stored PNG/JPEG/WebP. Draft can be inspected by administrators but is explicitly marked approval required; this does not relax Composition/public approval gates. Posters/characters/illustrations never substitute for a required real photo. Person/event/facility require exact named evidence. Explicit event year conflicts are excluded. Place evidence is always possible_match. Unsupported original formats (AI/PSD/PDF/SVG) and external-URL-only assets remain in asset management and are not thumbnail candidates.

Scoring components (0–100 heuristic points, not probability): subject 45, kind 20, context up to 10, location up to 8, time up to 8, usage tags 5. recencyBonus=0: updated time is not a shooting date. Tie order: score, exact subject, approval, updated timestamp, asset ID. Top 3 default; pure rank limit capped at 5. Distinguish strong_match/possible_match/no_match/missing_required_asset/not_supported.

SHA-256 match key covers safe article text/type/public info/paragraph snapshot, director-related priority/urgency/publication, matching spec and same-project asset metadata/active/approval/update snapshots plus matcher version. Asset paths, signed URLs, tokens, preview hrefs and provider private provenance are excluded. No recommendation DB write. Read-only refresh gets fresh article/assets; changed keys clear local selection, failed/empty results clear selection. Article/template rerenders do not execute provider calls.

Administrator-only ID thumbnail proxy verifies requested project ownership/access, active institutional source, draft/approved, private supported bucket and raster MIME before reading storage. No raw paths or signed URLs in candidate response. Existing public/review/GPT/Canva/information-graphic contracts are unchanged. No migration, external API, approval or automatic article placement.

Validation: 20 matching/security/UI tests plus full 249-test regression suite. Actual local React browser fixtures verified Top 3, single selection/change, same-key selection retention, changed asset key and changed article selection reset, no-match and other-strategy hiding. 1440/768 overflow=0 and console error=0. Thumbnail fixtures are synthetic raster squares; no claim of visual identity verification. API/proxy ownership/auth and active/source gates tested with mocked REST responses. No live institutional asset upload, customer data edits or Production data writes.
