# Composition 복사 안전성 보강 v1

## 변경 범위

기준 main `7b169b7228f8a60516213358940d0deb02b07548`. 단건·일괄 복사는 기존 RPC를 그대로 사용한다. 신규 endpoint, SQL, DB·Storage·인증 변경은 없다.

- 원본 선택 시 기존 인증 `GET /api/project-article-composition?projectSlug=…&articleId=…`로 Composition·자산을 조회한다. 배치 개수·슬롯·Draft/Approved·숨김 상태를 표시한다. GET은 기존 기사·자산·Composition/배치 조회를 재사용하므로 기사 수에 따른 초기 N+1 조회는 추가하지 않는다.
- 빈 원본·조회 실패는 기본 차단하며 예외적인 빈 원본 복사 기능은 제공하지 않는다. 명시적 적용 확인 뒤 실행 직전에 다시 GET하고, 빈 원본 또는 처음 확인한 원본과 달라졌으면 POST하지 않고 재확인을 요구한다.
- 복사 범위 안내를 통합한다. 자산 배치만 교체하며 HTML 텍스트 디자인·글꼴·제작 패턴·기사 내용은 유지된다. 대상 Composition은 draft다. 원본 자산은 공유 참조이며 복제·보존하지 않는다.
- 기존 복사 응답에만 `copyOutcome: success | rejected | unknown`을 추가한다. 입력·권한 검사 또는 인식 가능한 RPC 거절은 rejected, 확인된 정상 receipt는 success다. 전송 오류·알 수 없는 응답·RPC 성공 후 저장본 조회 실패는 unknown이다. 다른 저장 동작의 응답 계약은 유지한다.

## 결과 불명과 잠금

POST 전 같은 탭의 sessionStorage에 프로젝트·대상 기사 ID만 기록한다. 인증정보·기사 본문·자산 파일은 기록하지 않는다. 저장할 수 없으면 POST하지 않는다. 이 표식은 페이지 전환·reload 후에도 같은 탭의 해당 프로젝트 복사를 차단한다. 명확한 성공·거절 receipt가 있을 때만 제거한다.

15초 조회/POST timeout, 응답 유실 또는 늦은 성공 응답에서는 자동 재시도하지 않는다. 결과 불명 상태의 “저장본 조회”는 GET만 실행하고 현재 배치 개수·status와 편집 화면 링크를 보여준다. 조회 성공·배치 일치도 이번 요청의 성공을 증명하지 못하므로 잠금을 해제하지 않는다. 단건 화면의 로컬 초안을 저장본으로 덮어쓰지도 않는다. 복사 버튼·대상 선택은 잠기며 영향을 받은 대상 기사의 편집 화면에서만 추가 Composition 변경과 글꼴 저장 충돌도 차단한다. 같은 프로젝트의 무관한 기사 작성·Composition 조정은 막지 않는다.

잠금은 서버의 발행 이력·요청키가 아니라 **탭 단위 사고 방지 장치**다. 다른 탭·브라우저의 실행을 막거나 관리자가 요청 결과를 확정하는 기능은 아니다. UI에서 추정하여 잠금을 해제하는 버튼은 제공하지 않는다. 서버 로그·DB 읽기 전용 실사 등 별도 확인이 필요하다. sessionStorage의 표식만으로 서버 성공 여부를 주장하지 않는다.

## 남는 경합과 계약 한계

최종 GET과 RPC 사이에 다른 작업자가 원본을 변경·비울 수 있다. 서버의 원자적 non-empty 조건 또는 expected revision 입력은 이번 범위에 없으므로 이를 완전히 방지하지 않는다. 기존 RPC가 실제로 복사한 배치가 공개 가능한 자산인지도 별도 공개 renderer 조건에 따른다.

대상의 동시 편집에 대한 새로운 stale 검사·자동 병합·되돌리기 기능은 추가하지 않는다. 원래 복사 RPC의 대상 배치 교체·잠금·transaction 계약을 유지한다. GET이 실패했다고 POST의 롤백을 선언하지 않는다.

## 검증

격리 fetch/storage fixtures로 단건·일괄 각각 정상 복수 배치, 빈 원본, 조회 실패, 최종 재조회 변경, 명확한 거절, 응답 유실, 저장본 조회 실패, abort timeout/늦은 성공, 중복 클릭, 기사 전환·reload 잠금 보존을 검증한다. 실제 컴포넌트 연결·API outcome과 repository의 RPC 성공 후 조회 실패도 별도 검증한다. 원문·기존 settings는 mutation payload에 넣지 않는다.

실제 기사/프로젝트 및 원격 DB·Storage에는 쓰지 않는다. 서버 transaction·다중 사용자 경합·원격 저장 E2E를 모의 테스트 완료로 대체하지 않는다. 기존 글꼴·기사 저장·Composition 초안 보호 회귀는 전체 테스트로 확인한다. C1 코드와 독립 발행 PR은 사용하거나 수정하지 않는다.
