# 기사 폰트 검색·선택 UX v1

## 저장·렌더링 계약

- 기존 기사 `title/body/caption/button_font_asset_id`는 `font_assets` ID를 저장한다. 프로젝트 기본값은 제목/본문 ID이며 기사 값이 비어 있으면 기존 reader의 상속 규칙을 따른다.
- 기존 패밀리 선택은 `getSelectableFontAssets`가 선택한 Regular 400 normal 대표 파일 ID를 저장한다. Regular가 없으면 기존 helper의 normal/첫 파일 fallback을 그대로 사용한다.
- 이번 UI도 패밀리 선택 시 같은 대표 ID를 저장한다. 기존 Bold 등 개별 파일 ID는 최초 렌더·검색·접기만으로 대표 ID로 치환하지 않는다. 비활성/누락 ID도 명시적으로 다른 패밀리나 기본값을 선택하기 전까지 보존한다.
- 패밀리의 실제 굵기·스타일을 안내하지만 새 굵기 선택/저장 모델을 만들지 않는다. 제목·본문의 실제 weight/style은 기존 CSS가 결정한다. 미리보기 샘플은 400 normal 기준이며 특정 굵기 적용을 보장하는 UI가 아니다.
- `font-css.ts`, 저장 API/DB, 공용 reader, 글자 확대, 폰트 등록·활성화 로직은 변경하지 않는다.

## 검색·그룹화

- `familyId`가 같은 파일만 그룹화한다. TTF/OTF 및 굵기/스타일을 하나의 그룹에서 확인한다. 패밀리 없는 기존 단일 파일은 개별 그룹이며 이름이 비슷하다는 이유로 합치지 않는다.
- 활성·웹 사용 허용·파일 URL 존재 및 패밀리 활성/웹 사용 허용 조건을 기존 helper와 동일하게 적용한다.
- 등록된 패밀리 표시명, family/name, CSS family, 원본 파일명에서 NFC·대소문자·공백 정규화 후 부분 일치 검색한다. 한글/영문 별명이 데이터에 있으면 양쪽으로 검색 가능하다. 저장되지 않은 번역명/음역명은 추정하지 않는다.
- 프로젝트 기본 제목/본문 폰트가 속한 패밀리를 우선 표시한다.
- 최초 40개, 명시적 '40개 더 보기'. 검색은 전체 후보에 적용한다. 검색어 변경 시 표시 한도를 초기화한다. 결과 없음과 표시 건수를 알린다.
- 제목/본문/캡션/행동 버튼 모두 공통 `SearchableFontSelect`를 사용한다. native listbox의 방향키 선택과 검색 입력을 제공하며 Enter는 기사 저장으로 이어지지 않게 차단한다.

## 실제 글꼴 미리보기

- 선택한 패밀리만 기존 `getFontFaceCss`로 선언한다. 전체 라이브러리의 폰트를 미리 다운로드하지 않는다.
- `document.fonts.load` 결과로 로딩/성공/실패 안내를 표시한다. 10초 지연 시 기본 글꼴로 보일 수 있음을 알리며 늦게 성공하면 성공으로 바뀐다. 선택 변경/언마운트 뒤 이전 결과는 무시한다.
- 글꼴 로딩 성공은 모든 글리프 지원 보장이 아니므로 미지원 문자의 fallback 가능성을 안내한다.
- 기사별 remount key를 유지한다. 새 API, dependency, migration, Storage 설정 변경 없음.

## 검증

- 신규 10개 회귀 테스트: ID 기반 그룹화/형식 중복, 실제 등록 face, 한영 검색/NFC, 비활성 필터, 프로젝트 기본값 우선, 600패밀리 검색·페이지 표시, 기존 Bold/누락 ID 유지, 필드 독립성, 키보드 선택·Enter 저장 방지, FontFaceSet 실패/늦은 응답, 기사 전환 remount 및 기존 CSS 계약.
- 전체 476/476 (격리 PGlite SQL 포함), TypeScript, lint, Webpack build, diff check. lint 기존 warning 3개, 신규 0개.
- 로컬 전용 임시 화면에 600파일/300패밀리와 긴 한영 이름을 렌더링해 390/768/1440px에서 overflow 0 확인. 임시 화면/폰트 파일은 빌드·커밋 전에 제거했다.
- 실제 Staging DB를 읽는 로컬 관리자 편집기에서 저장된 NanumGothic 제목/NanumMyeongjo 본문 복원, 독립 선택, 결과 없음, 실제 폰트 요청 200, 공통 저장본 iframe과 최대 글자 크기 확인. console error 0. 폰트 로드 실패 안내도 확인했다. 로컬 fixture WOFF2 성공 및 실제 Staging TTF 요청 200 확인.
- 브라우저 샘플 선택은 로컬 UI에서만 수행했으며 기사 저장·발행·등록·DB/Storage write는 실행하지 않았다.
- Staging 프로젝트는 비공개이므로 익명 공개 reader를 새로 발행해 검증하지 않았다. 공용 reader의 관리자 저장본 경로 및 기존 자동화 회귀로 확인했으며, 익명 발행 화면 실제 재검증은 미수행이다. Production 배포/데이터 변경 없음.

## 제한 및 후속

- 개별 weight/style 저장을 새로 도입하지 않는다. 실제 등록된 굵기는 확인 정보다.
- 한영 검색 범위는 저장된 이름에 한정된다.
- 실제 등록 폰트 수백 건의 원격 DB 환경 대신 600패밀리 pure-function 테스트와 300패밀리 브라우저 fixture를 사용했다. 전체 파일 다운로드는 하지 않는다.
- 폰트 삭제·즐겨찾기·라이선스 workflow는 범위 밖이다.
